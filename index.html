🗃️ Introducción a Bases de Datos

¿Qué es una BD relacional? ¿Por qué no basta con Excel?

📖

¿Qué es una Base de Datos Relacional?

▼

Una base de datos relacional organiza la información en tablas relacionadas entre sí. Es como Excel con superpoderes: maneja millones de datos, múltiples tablas conectadas y accede a cualquier información en milisegundos con SQL.

📋

Tabla

Estructura fundamental. Ej: Alumnos.

📏

Columna/Campo

Categoría de dato. Ej: nombre, edad.

📄

Registro/Fila

Entrada completa de un elemento.

🔑

Clave Primaria

ID único que distingue cada registro.

🔗

Relación

Conexión entre dos tablas. Ej: Clientes↔Pedidos.

🔄

SGBD

Software que gestiona la BD. SQLite, MySQL…

💡

Curiosidad histórica: El modelo relacional fue inventado por Edgar F. Codd en 1970 en IBM. Su artículo "A Relational Model of Data for Large Shared Data Banks" cambió la informática para siempre. Sin él no existiría SQL.

🎓 Igor dice: La clave es evitar la redundancia. En lugar de repetir "Matemáticas" en 200 filas de alumnos, guardas el ID del curso una vez. Si cambia el nombre, solo lo cambias en un sitio.
🧠

Lo que nadie suele contarte: Las BDs relacionales se basan en la teoría de conjuntos matemática. Cada tabla es un conjunto, y las operaciones SQL (JOIN, UNION, etc.) son operaciones de conjuntos. SQL = álgebra relacional aplicada.

🆚

BD Relacional vs Excel: las diferencias clave

▼
CaracterísticaExcelBD Relacional
Datos repetidosFrecuentesMinimizados (normalización)
Integridad de datosManualAutomática (FK, CHECK)
Millones de filasLento o imposibleOptimizado
Múltiples usuariosConflictosControl de concurrencia
Relaciones entre datosComplicadoDiseñado para ello
Consultas complejasFórmulas difícilesSQL legible y potente

📊 Tipos de Datos en SQLite

Qué tipo asignar a cada columna. SQLite usa un sistema llamado "afinidad de tipos".

📋

Los 5 tipos de almacenamiento

▼
TipoDescripciónEjemploUso típico
NULLAusencia de valor—Campo opcional vacío
INTEGEREnteros con signo (1-8 bytes)42, -7, 0Edades, IDs, cantidades
REALDecimal flotante (8 bytes)3.14, 9.99Precios, pesos, temperaturas
TEXTCadena de texto UTF-8"Hola Igor"Nombres, emails, direcciones
BLOBDatos binarios tal cualfoto.jpgImágenes, archivos
BOOLEAN → INTEGER (0/1)FECHA → TEXT 'YYYY-MM-DD'DINERO → REAL o INTEGER céntimos
🤯

Lo que nadie suele contarte: SQLite es débilmente tipado. Puedes guardar un TEXT en una columna INTEGER sin error. MySQL o PostgreSQL lanzarían un error. Por eso SQLite es más permisivo pero también más peligroso si no controlas los tipos.

✅

Restricciones de columna (Constraints)

▼
CREATE TABLE alumnos (
  id      INTEGER PRIMARY KEY AUTOINCREMENT,
  nombre  TEXT    NOT NULL,
  edad    INTEGER CHECK(edad >= 0 AND edad <= 120),
  email   TEXT    UNIQUE NOT NULL,
  saldo   REAL    DEFAULT 0.0,
  activo  INTEGER DEFAULT 1 CHECK(activo IN(0,1))
);
Constraint¿Qué hace?
NOT NULLCampo obligatorio. No puede estar vacío.
UNIQUENo puede haber dos filas con el mismo valor.
DEFAULTValor por defecto si no se especifica.
CHECKValida que el valor cumpla una condición.
PRIMARY KEYIdentifica únicamente cada fila.
AUTOINCREMENTAuto-genera el siguiente entero (nunca reutiliza IDs borrados).

🔑 Primary Key y Foreign Key

El alma de las bases de datos relacionales.

🏅

PRIMARY KEY — La clave primaria

▼

La Primary Key es el "DNI" de cada registro. Reglas: solo 1 por tabla, nunca NULL, siempre única, no cambia.

CREATE TABLE cursos (
  id      INTEGER PRIMARY KEY AUTOINCREMENT,
  nombre  TEXT    NOT NULL,
  precio  REAL
);
🔗

FOREIGN KEY — La clave foránea

▼
CREATE TABLE alumnos (
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  nombre    TEXT    NOT NULL,
  curso_id  INTEGER,
  FOREIGN KEY (curso_id) REFERENCES cursos(id)
    ON DELETE SET NULL
    ON UPDATE CASCADE
);
ON DELETE¿Qué pasa con los hijos?
CASCADESe borran automáticamente con el padre.
SET NULLLa FK del hijo pasa a NULL.
RESTRICTError: no se puede borrar el padre si tiene hijos.
NO ACTIONIgual que RESTRICT (por defecto).

🗑️ DELETE y DROP TABLE

Borrar registros o tablas. Sin Ctrl+Z.

🗑️

DELETE vs DROP TABLE

▼
DELETE FROM alumnos WHERE id = 3;
DELETE FROM alumnos; -- vacía la tabla (estructura intacta)
DROP TABLE alumnos;   -- borra tabla entera (datos + estructura)
DROP TABLE IF EXISTS alumnos; -- más seguro
⚠️ No hay DESHACER. Haz siempre backup antes de sentencias destructivas.

🔨 ALTER TABLE

Modificar tablas existentes. SQLite tiene limitaciones importantes.

🔨

¿Qué puedes y no puedes hacer?

▼
-- ✅ Renombrar tabla
ALTER TABLE alumnos_new RENAME TO alumnos;
-- ✅ Añadir columna
ALTER TABLE alumnos ADD COLUMN telefono TEXT;
-- ✅ Renombrar columna (SQLite 3.25+)
ALTER TABLE alumnos RENAME COLUMN saldo TO presupuesto;
-- ❌ NO PUEDES eliminar columnas directamente
🤔

Truco profesional para eliminar columna: CREATE TABLE nueva (sin la columna) → INSERT INTO nueva SELECT cols FROM vieja → DROP TABLE vieja → ALTER TABLE nueva RENAME TO vieja.

👁️ SELECT y WHERE

El comando más usado. SELECT nunca modifica datos, solo lee y devuelve.

👁️

SELECT completo

▼
SELECT * FROM alumnos;
SELECT nombre, edad FROM alumnos;
SELECT nombre AS alumno, edad AS años FROM alumnos;
SELECT nombre, saldo * 1.21 AS con_iva FROM alumnos;
SELECT nombre || ' tiene ' || edad || ' años' AS frase FROM alumnos;
SELECT IFNULL(edad, 0) FROM alumnos;
SELECT DISTINCT curso_id FROM alumnos;
SELECT * FROM alumnos WHERE edad > 20 AND curso_id = 1;
SELECT * FROM alumnos WHERE saldo IS NULL;
💡 Igor dice: SELECT * es cómodo para explorar pero malo en producción. Especifica siempre las columnas que necesitas.
🔢

El || en SQLite: Para concatenar texto SQLite usa || (barras verticales). En MySQL: CONCAT(). En SQL Server: +. || es el estándar SQL ANSI.

▼

🔀 JOINs — Combinar Tablas

El comando más potente de SQL. Une información de múltiples tablas relacionadas.

🔀

INNER JOIN y LEFT JOIN

▼

JOIN combina datos de tablas relacionadas. Si alumnos tiene curso_id pero quieres ver el NOMBRE del curso, necesitas unirte a la tabla cursos.

-- INNER JOIN: solo alumnos CON curso asignado
SELECT a.nombre, c.nombre AS curso
FROM alumnos a
INNER JOIN cursos c ON a.curso_id = c.id;

-- LEFT JOIN: todos los alumnos, tengan o no curso
SELECT a.nombre, c.nombre AS curso
FROM alumnos a
LEFT JOIN cursos c ON a.curso_id = c.id;

-- JOIN de 3 tablas
SELECT a.nombre, c.nombre AS curso, p.nombre AS profesor
FROM alumnos a
JOIN cursos c     ON a.curso_id    = c.id
JOIN profesores p ON c.profesor_id = p.id;

-- JOIN + GROUP BY
SELECT c.nombre, COUNT(a.id) AS total
FROM cursos c
LEFT JOIN alumnos a ON a.curso_id = c.id
GROUP BY c.id, c.nombre
ORDER BY total DESC;
JOIN¿Qué muestra?Sin coincidencia
INNER JOINSolo filas con pareja en AMBAS tablasNo aparece
LEFT JOINTodo de la tabla izquierdaNULL en columnas de la derecha
💡

Alias de tabla: Con múltiples tablas es obligatorio usar alias (a, c, p) para distinguir columnas con el mismo nombre. SELECT a.nombre, c.nombre diferencia el nombre del alumno del nombre del curso.

📐 Normalización

1FN, 2FN, 3FN. Diseño eficiente sin redundancias ni anomalías.

1️⃣

1FN — Primera Forma Normal

▼

Regla: Cada celda debe tener un único valor atómico (indivisible). No puede haber listas o grupos repetidos en una celda.

❌ Viola 1FN:

alumno_idteléfonos
1666111, 699333

✅ Cumple 1FN:

alumno_idtelefono
1666111
1699333
2️⃣

2FN — Segunda Forma Normal

▼

Regla: Cumplir 1FN + cada atributo no clave depende de TODA la clave primaria. Aplica a tablas con PK compuesta.

En la práctica: En una tabla matriculas(alumno_id, curso_id, nombre_alumno), el nombre_alumno solo depende de alumno_id, no del par completo → hay que moverlo a la tabla alumnos.
3️⃣

3FN — Tercera Forma Normal

▼

Regla: Cumplir 2FN + no debe haber dependencias transitivas. Ningún atributo no clave debe depender de otro atributo no clave.

❌ Viola 3FN:

alumno_idcpciudad
128001Madrid

Ciudad depende de CP, no de alumno_id

✅ Cumple 3FN:

cpciudad
28001Madrid

Tabla codigos_postales separada

👓 Vistas y Transacciones

CREATE VIEW, BEGIN/COMMIT/ROLLBACK, índices. SQL avanzado imprescindible.

👓

CREATE VIEW — Consultas guardadas

▼

Una vista es una consulta SQL guardada con nombre. Se comporta como una tabla virtual. Útil para simplificar consultas complejas y reutilizarlas.

-- Crear una vista
CREATE VIEW alumnos_con_curso AS
  SELECT a.nombre, a.edad, c.nombre AS curso, c.precio
  FROM alumnos a
  JOIN cursos c ON a.curso_id = c.id;

-- Usar la vista como si fuera una tabla
SELECT * FROM alumnos_con_curso WHERE precio > 100;

-- Eliminar la vista
DROP VIEW alumnos_con_curso;
💡

Lo que nadie suele contarte: Las vistas en SQLite son de solo lectura. No puedes hacer INSERT/UPDATE/DELETE sobre una vista en SQLite (en PostgreSQL y MySQL sí en ciertos casos). Las vistas no almacenan datos, ejecutan la consulta cada vez que se accede.

🔄

Transacciones — Todo o nada

▼

Una transacción agrupa varias operaciones SQL en un bloque atómico: o se ejecutan TODAS con éxito, o no se ejecuta NINGUNA.

-- Transferencia bancaria (clásico)
BEGIN;
  UPDATE cuentas SET saldo = saldo - 500 WHERE id = 1;
  UPDATE cuentas SET saldo = saldo + 500 WHERE id = 2;
COMMIT;   -- confirmar todo

-- Si algo falla: deshacer todo
ROLLBACK;
Las propiedades ACID: Atomicidad (todo o nada), Consistencia (la BD siempre queda en estado válido), Isolamiento (las transacciones no se interfieren), Durabilidad (una vez confirmada, persiste aunque falle el sistema).
⚡

Índices — Acelerar consultas

▼

Un índice acelera las búsquedas en columnas que se consultan frecuentemente con WHERE o JOIN.

-- Crear índice en email (búsquedas frecuentes)
CREATE INDEX idx_alumnos_email ON alumnos(email);

-- Índice único
CREATE UNIQUE INDEX idx_email_uniq ON alumnos(email);

-- Ver índices de una tabla
PRAGMA index_list('alumnos');

-- Eliminar índice
DROP INDEX idx_alumnos_email;
⚠️ Los índices no son gratuitos: Aceleran SELECT pero ralentizan INSERT/UPDATE/DELETE porque hay que actualizarlos. Úsalos solo en columnas que consultas muy frecuentemente con WHERE o JOIN.
